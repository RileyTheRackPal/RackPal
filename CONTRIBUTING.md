# Contributing to RackPal

RackPal is an **alpha**, published to collect feedback from people who design, build and document
A/V racks. For now that is the whole of how to contribute.

## Issues: yes, please

[Open an issue](https://github.com/RileyTheRackPal/RackPal/issues/new/choose). There are two forms:

- **Bug report**: something RackPal did wrong. It asks for the version (`Help` ▸ `About RackPal…`),
  your Windows version and the steps.
- **Workflow feedback**: where RackPal does not match how you actually work. This is the feedback
  the alpha exists for, and it is worth sending even when nothing crashed.

**Do not attach a real client's project file.** A `.rppj` holds site addresses, room names and
contact details. Reproduce the problem in a starter project or a scratch project instead.

## Pull requests: not yet

Pull requests are **not accepted during the alpha**, and one opened will be closed with thanks.
This is a decision about the alpha, not about you: the project's history is held to a single
identity by a gate (DR-258), and the contribution terms DR-036 rules (a DCO sign-off) are deferred
until contributions open (DR-259). Both are in
[docs/canonical-decisions.md](docs/canonical-decisions.md). If you have a fix, describe it in an
issue; that is genuinely useful.
